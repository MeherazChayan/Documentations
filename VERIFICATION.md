# Verification and publication checklist

This is a **source-grounded documentation draft**, not a claim of independent end-to-end validation.

## Verified against public GitHub pages

- The five source repository identities and their visible README descriptions.
- NewsProof: documented stack, routes, environment variables and commands.
- My University Portal: prototype scope, routes, technology, commands and simulation boundary.
- MedBot Assist: artifact paths, sensor functions and explicit safety restrictions.
- Care Cloud: repository structure, described features and public deployment URL.
- ReliableVAEP: research method, notebook names, dataset periods and README results.

## Not independently verified

- Runtime behavior, installation and build commands for the underlying projects.
- Schema-level accuracy of the NewsProof API endpoints against current code.
- Care Cloud live deployment behavior and environment setup.
- MedBot hardware wiring and physical operation.
- Re-execution of ReliableVAEP notebooks or statistical outputs.
- Full source-code review and permission review for reuse of diagrams or other assets.

## Before calling these documents final personal writing samples

1. Clone each upstream repository and compare the site against its current source tree.
2. Execute the documented safe development and test steps in an isolated environment.
3. Inspect all technical details, rewrite/edit the prose personally, and confirm authorship.
4. Check sensitive material and publication rights before exposing any assets.
5. Install documentation dependencies and run the Sphinx strict build.
6. Check external links; publish only after these checks pass.

No placeholder API payloads, fabricated test outputs, unverified hardware wiring,
or invented deployment credentials are included.
